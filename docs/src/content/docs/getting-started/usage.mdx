To use `ghtui`, follow these steps after you've [installed it][01]:

1. Run

   ```bash
   ghtui
   ```

2. Press <kbd>?</kbd> for help.
3. Run `ghtui --help` for more info:

   ```bash
   Usage: ghtui [OPTIONS]

   Options:
     -c, --config <FILE>  Use this configuration file instead of a .ghtui.yml in the git repo, $GHTUI_CONFIG, or $XDG_CONFIG_HOME/ghtui/config.yml
         --debug          Write debug output to debug.log
     -v, --version        Print version and exit
     -h, --help           Print help
   ```

## Flags

### `--config`

Specify the path to a configuration file to use for the dashboard. If the configuration file
doesn't exist or is invalid, `ghtui` returns an error.

```bash
ghtui --config path/to/configuration/file.yml
```

| Aliases |  Type  | Default                                                                                                                   |
| :------ | :----: | :------------------------------------------------------------------------------------------------------------------------ |
| `-c`    | String | `.ghtui.yml` file if inside a git repo, `$GHTUI_CONFIG` env var, or if not set, `$XDG_CONFIG_HOME/ghtui/config.yml` |

If you don't specify this flag, `ghtui` uses the default configuration.
If the file doesn't exist, `ghtui` will create it.

The location of the default configuration file depends on your system:

1. If `$GHTUI_CONFIG` is a non-empty string, `ghtui` will use this file for
   its configuration.
2. If `$GHTUI_CONFIG` isn't set and you're in a git repository, it will look for `.ghtui.yml` or `.ghtui.yaml`
   in the repository root.
3. If neither of the above applies, then:
   - If `$XDG_CONFIG_HOME` is a non-empty string, the default path is `$XDG_CONFIG_HOME/ghtui/config.yml`.
   - If `$XDG_CONFIG_HOME` isn't set, then:
     - On Linux and macOS systems, the default path is `$HOME/.config/ghtui/config.yml`.
     - On Windows systems, the default path is `%USERPROFILE%\.config\ghtui\config.yml`.

For more information about authoring configurations, see [Configuration][02].

### `--debug`

Specify whether `ghtui` should write logs to the `debug.log` file in the current directory. By
default, `ghtui` doesn't output debug information.

```bash
ghtui --debug
```

| Aliases |  Type   | Default |
| :------ | :-----: | :------ |
| (None)  | Boolean | `false` |

When you use this flag, `ghtui` creates the `debug.log` file in the current directory if it doesn't exist. If the file does exist, `ghtui` appends new log entries to it.

### `--help`

Use this flag to display the help information for `ghtui` in the terminal. If you specify this
flag, `ghtui` ignores all other flags. It only displays the help information.

```bash
ghtui --help
```

| Aliases |  Type   | Default |
| :------ | :-----: | :------ |
| `-h`    | Boolean | `false` |

### `--version`

Use this flag to display the version information for `ghtui` in the terminal. If you specify this
flag with the `--config` or `--debug` flags, `ghtui` ignores them. It only displays the version
information.

```bash
ghtui --version
```

| Aliases |  Type   | Default |
| :------ | :-----: | :------ |
| `-v`    | Boolean | `false` |

When you use this flag, `ghtui` prints its name and version:

```text
ghtui 0.1.0
```

## Default Keybindings

When you use `ghtui`, it displays the dashboard as a terminal UI (TUI). In the TUI, you can use
several commands by pressing key combinations to navigate and interact with the dashboard.

You can press the <kbd>?</kbd> key to open the help popup. It lists the keybindings for the current
context, grouped by category. Press <kbd>esc</kbd> to close it.

You can press the <kbd>q</kbd> key to quit the dashboard and return to your normal terminal view.

For more information about the keybindings for the dashboard, see [Keybindings][04].
